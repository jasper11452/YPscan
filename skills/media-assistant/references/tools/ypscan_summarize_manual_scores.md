# ypscan_summarize_manual_scores

Risk tier: local read and aggregate workbook save; no remote calls.

Only for manual sourcing. Call after normalized links are saved and after every `manual_score_batch` save. The sole argument is `requirement_id`, the current requirement ID. Do not supply paths, counts, recommendation labels or a batch size.

The tool uses registered requirement mode/platform/quantity, hash-verified normalized links, observed native completion success/failure IDs and saved scoring workbooks. Those source records (mode, platform, quantity, links path+SHA-256, per-batch completion IDs and scoring workbook paths+SHA-256) are persisted per project and rehydrated on demand, so a gateway reset no longer invalidates an already scored batch; every rehydrated file is re-hashed before use. Missing or changed records are an explicit stop, not authorization to recreate a requirement or repeat paid scoring. It selects candidates from the gradient pool (10→30, 20→50, 50→100) in original order. The first scheduled batch is at most `min(20, quantityTotal)`; later batches are at most 20. It counts distinct creators with the exact conclusion `推荐`; `不推荐` does not count. Other verdicts, conflicting duplicates, changed files, foreign IDs/platforms/requirements or missing context stop automatic processing. All-failed completion batches (no csv_file) are still registered with their failed_author_ids, so failed creators are not rescheduled; an explicit retry that succeeds supersedes the earlier failure record.

- `next_action=complete_next_batch`: use only `next_author_ids` for the current platform native completion tool (Xiaohongshu `page_count=1`), then upload only this batch’s completion CSV and score it. Do not prefetch later batches.
- `next_action=await_scores`: completed creators still lack scoring rows. This takes precedence over target reached and candidate exhaustion, so a partially returned current batch cannot be delivered early. Show `progress.user_visible_message` as an explicitly non-final stage result and never present the saved batch workbook as the final summary. While the job is running, wait only for the current submitted job (30-second polling, at most 10 polls per round) and do not start another batch. If it is already terminal with rows still missing, report `pending_score_author_ids` and stop instead of resubmitting or guessing.
- `next_action=deliver`: recommendation target reached or candidates exhausted. Show `delivery.local_file_link` if present and stop further completion/scoring. Report `recommended_count`, `target_count`, `scored_count`, `unprocessed_count`, `completion_failed_count` and `shortfall` accurately. No file means no claimed delivery.

When the summary itself fails (any error except inquiry `MODE_NOT_APPLICABLE`), first report the real error. If the persistent source record still holds scoring workbooks for this requirement whose path, SHA-256, requirement ID and platform all verify, the result carries them under `data.partial_delivery.batch_files`. Show those local links explicitly labeled `本批评分结果，汇总未完成` (this batch's scoring result, summary incomplete), never as the final summary. Do not re-run search, native completion or scoring, do not rebuild a requirement, and do not ask the user to redo the whole round. Batches that fail verification are omitted; never guess, rebuild or substitute a missing file.

The final workbook retains the Provider single-sheet template, sheet name, titles, requirement metadata, grouped headers, column widths, colors, numeric formats, frozen rows and cell types. It updates the workbook's scored-count cells to the delivered rows and includes every scored row whose Provider relevance score is non-zero; it does not filter verdicts or truncate to N. In the final workbook the `综合得分` column is rewritten with a blended score = 0.7 × Provider relevance score + 0.3 × batch cost-effectiveness score, and rows are sorted by that blended score descending (ties by cost-effectiveness). Cost-effectiveness is a same-platform, same-batch percentile (cheaper is better) built from Douyin `植入视频-预期CPM` (60%) and `植入视频-预期CPE` (40%), or for Xiaohongshu from the proxy `视频笔记一口价 ÷ 合作_视频&图文_阅读中位数 × 1000` (falling back to the daily median) and `视频笔记一口价 ÷ 合作_视频&图文_互动中位数` (same fallback). Missing cost data is imputed with the batch median and reported through `cost_effectiveness_pending_count`; when the batch has no usable cost data, the original relevance score is kept. The `匹配等级` column remains the Provider relevance tier and the Provider template itself is not modified. Rows whose Provider relevance score is `0` (usually failed, invalid or data-insufficient evaluations, but also valid evaluations whose content and type relevance are both level 0) stay out of the final workbook, still count as returned rows (never as missing rows), never count as recommendations, and are reported through `excluded_zero_score_count`. Unscored candidates are not labeled as rejected. Sorting the scored rows does not establish global optimality across unscored candidates. Intermediate files remain preserved, repeated identical summaries within the same second are idempotent, and the delivered workbook is named `<project name>-手动拓展汇总表-<YYYYMMDD-HHmmss>.xlsx` using the requirement's Agent-summarized `projectName` (for example `天猫9月男装衬衫-手动拓展汇总表-20260910-153045.xlsx`); the project name segment is omitted when no project name is available, and a same-second name already holding different content gets the content SHA-256 first 8 characters appended instead of being overwritten. Style tables may differ by trailing entries in number formats, fonts, fills, borders or style lists when all overlapping entries and other style metadata match; the summary retains the union without changing style IDs (including single-row batches that omit alternating-row styles). When writing the sorted workbook it re-applies the template's own alternating-row fill by final row order, using only one-to-one style pairs that differ solely by fill ID; a missing, ambiguous or order-conflicting pairing leaves every style untouched and never adds fill definitions. Conflicting style IDs, incompatible style metadata, different shared strings, formulas, data-area merges or linked objects that cannot be safely moved stop with YPSCAN_MANUAL_SCORE_TEMPLATE.

In the final summary only, any cell whose text is a single valid HTTP(S) URL becomes an Excel external hyperlink mapped to its sorted creator row, regardless of column. Display text, cell styles and source workbooks remain unchanged. Cells that are not a single valid URL remain literal text. This does not check remote availability or enable merging source templates that already contain hyperlinks or other unsupported linked objects.

On exhausted shortage, deliver real results first, then review. Prioritize same-topic keyword changes and reduced non-core persona restrictions; execute this priority scope when already authorized, otherwise request confirmation. If still insufficient, suggest other eligible conditions under the Skill and wait for explicit confirmation of that item. Never use this tool for inquiry retrieval. Gateway reset removes source registrations; missing context is an explicit stop, not authorization to recreate a requirement or repeat paid scoring.

Errors use `YPSCAN_MANUAL_SCORE_*`: source/context mismatch, changed sources, missing/ambiguous headers, unknown verdict, invalid score, conflicting results, limits and read/save failures. Keep prior files and report the error. Never fall back to shell scripts or guess the recommendation count.

`MODE_NOT_APPLICABLE` means the registered requirement mode is inquiry retrieval; no workbook is read or changed. Do not retry or show a retry dialog. Deliver only an already successfully saved scoring workbook for this requirement; without a trusted save result, report the missing evidence and stop. `CONTEXT_UNAVAILABLE` means the persistent source record has no trusted context for this requirement and no verified batch workbook to deliver; it remains a stop without retry, recreation or rescoring, and it does not establish inquiry mode or completed delivery.
