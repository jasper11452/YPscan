# AskUserQuestion（宿主交互对话框）

需要用户选择、补充、确认或决策时，必须调用宿主 `AskUserQuestion`，不得用普通聊天文本提问。只要下一步依赖任何用户回复，就在同一轮调用本工具，绝不以问句、让用户打字或被动等待作为最终回复。问题只问用户可决定的、且缺失会实质改变结果的事项。

## 参数结构

```json
{
  "questions": [
    {
      "header": "标题（必填，如：悦普识星确认 / 悦普识星决策 / 下一步）",
      "question": "问题正文（必填，完整上下文）",
      "options": [{ "label": "选项短标签（必填）", "description": "选项说明（必填）" }],
      "multiSelect": false
    }
  ]
}
```

## 数量上限

- 一次调用最多 **4 个问题**；每个待澄清字段使用一个问题，并在同一次调用中成组提交。超过四项时，用户回答后重新解析，再提交下一组问题；不得把多个字段合并成警告。
- 每个问题 **2–4 个选项**，label 和 description 均非空。
- 选项必须是可执行的答案或动作：用户只点击 label 就能让流程继续，不能再要求用户另行输入该选项本该承载的值。
- 禁止使用“返回补充”“确认并补充”“自行填写”“请输入”等伪选项。对过期或缺失的时间，必须给出至少两个未来的绝对日期时间；对可编码的“不限”，直接规范化而不弹窗。
- `multiSelect` 省略等同 `false`；`true` 表示可多选（答案可共存），`false` 表示单选（答案互斥）。
- 普通选项弹窗由宿主保留自定义输入入口。不要添加虚假的 `其他` 选项、自定义字段参数或封闭式限制，也不要替用户选择默认答案。
- 数值字段澄清（如报价、粉丝、返点、数量或截止时间）每题必须显式设置 `multiSelect: false`，并提供恰好 3 个互斥、可直接作为该字段答案的具体值。不得只提供 1 个真实数值，再搭配“返回修改”“返回补充”“取消”或“结束”等动作选项；恰好 2 个选项可能被宿主渲染成没有自定义输入入口的按钮确认弹窗。
- 数值字段的 `question` 必须先说明当前需求为何无法确定该值，再明确提示用户“请选择或自定义输入”具体要求。完全未提及时直接说明缺少哪个字段；只有定性描述时引用或准确概括相关原话，并说明它不能唯一确定哪个数值边界。不得只写“确认报价”“报价上限是多少”，也不得向用户展示“落库”“Provider 参数”等内部实现术语。例如：
  - `您的需求没有提及报价要求，\n请选择或自定义输入报价上限。`
  - `您的需求中只说了“行业头部达人”，\n没有明确粉丝数要求，\n请选择或自定义输入具体粉丝数范围。`

## 展示规则

- `header`：简短分类标题；超过 20 个 Unicode 字符时同样换行。
- `question`：承载完整上下文（如缺失字段清单、风险提示；**MCN 机构名单表格除外**——它必须在调用 `AskUserQuestion` 前作为用户可见正文展示，`question` 只写决策问题；**询价发送确认除外**——最终机构名单和完整企微消息必须写入警示弹窗正文）。内容太长必须**主动换行**：
  - `header`、`question`、`label` 和 `description` 的每一行都不得超过 20 个 Unicode 字符；
  - **只在整行将超过 20 个 Unicode 字符时才换行**：先按原文连续写满接近 20 个字符，确需断行时优先选语义边界（标点或词语之间），连续长文本仍必须硬切分，多行用 `\n` 连接；不要把每个短分句、字段、项目名或短语单独成行；
  - 保留原消息已有的行结构：企微消息本身每个字段一行，就保持字段行不变，只对超过 20 字符的单行断行，不得给短行添加额外换行；
  - 机构名等选项标签超长时允许插入展示换行，后续匹配前仅移除换行，还原原始完整名称。
- `label`：短动作词（如 `询价机构`、`结束本次`、`选择候选机构`），超长时按上述规则换行。
- `description`：一句话补充该选项后果，按上述规则换行。

## 展示模式与时机

`AskUserQuestion` 没有独立的 `type` 参数，但宿主按结构区分两种渲染形态：

- **选项弹窗**：普通形态，一次 1–4 个问题，每题 2–4 个选项卡片（label 和 description 都展示），用于澄清、消歧、多选等。
- **警示弹窗**：一次调用恰好 1 个问题、恰好 2 个选项且 `multiSelect` 不为 `true`（省略或 `false`）时，宿主以警示样式渲染：正文完整展示 `question`（保留换行），两个选项只显示 label 作为主/次按钮，**选项的 description 不展示**。全部决策内容必须写在正文里，不得把内容拆成选项；正向动作词（如 `确认发送`）成为主按钮，否定动作词（如 `返回修改`）为次按钮。

| 类型     | 结构                                          | 示例                    |
| -------- | --------------------------------------------- | ----------------------- |
| 选项弹窗 | 1–4 题，每题 2–4 个选项                       | `询价机构` / `手动拓展` |
| 多选     | multiSelect=true                              | 多平台、多字段同时确认  |
| 警示弹窗 | 1 题、恰好 2 个选项、multiSelect 省略或 false | `确认发送` / `返回修改` |

- **候选消歧**：当 Provider 返回机构名模糊或不唯一候选时，只展示真实候选并让用户选择；不得把已经成功发送的机构放入后续调用。
- **询价发送确认**：调用 `create_with_distributions` 前，必须用警示弹窗确认：一次调用 1 个问题、恰好 2 个选项 `确认发送`/`返回修改`、不设 `multiSelect`；最终机构名称列表和完整企微消息写入问题正文（保留换行），不得把机构或消息拆成选项，选项只写动作词。用户选择 `确认发送`，或在该预览后明确回复“可以发”“发吧”“按这个发”“就这样发送”等无条件肯定表达时，可发送一次；否定、要求修改或带条件的表达不算确认。
- **不得预设答案**：选项顺序不表示推荐；用户拒绝/取消/关闭/超时/缺失答案是当轮终止，不得替用户推断或代选。

## Hook 生成的问题

- Hook 或保存结果给出 `ASK_USER_QUESTION_ARGS` / `delivery.next_args` 时，**逐字原样传递**，不得改写、删减或重排。
- 用户已明确说出 `询价机构` 或 `手动拓展` 时直接采用；`直接手扒`、`手扒`、`人工拓展`、`手捞筛选` 作为旧输入别名统一映射为 `手动拓展`。未明确、同时提到两种模式或语义冲突时，首次业务动作使用固定问题选择模式，回答前不解析、不落库。询价功能的 `rank_mcns` 排序成功后先输出完整 MCN 表格，再保存排名表并展示本地链接，最后调用保存结果给出的收件机构选择问题；不得再次询问业务模式。MCN 为空或手动拓展返回可信不足数量时，先按 Skill 复核原需求、解析输出、实际落库参数和当前结果，确认正确后才按 Skill 优先调整同主题关键词、减少非核心人设限定，用户已明确要求该优先范围放宽时直接执行，否则先等待确认；调整后仍不足再逐项建议其他条件并等待该项确认；每个放宽轮次创建新 requirement 并重新选择字段。全部允许项用完仍不足时，询价机构询问“手动修改需求 / 改用手动拓展 / 结束”，手动拓展询问“手动修改需求 / 改用询价机构 / 结束”。同一会话需求条件未变、前一功能完成或明确停止后改用另一功能时，也必须重新解析、复核并创建新 requirement，且按新 requirement 重新选择字段。唯独当前机构列表后的“暂不询价”、关闭/取消弹窗或当轮未回答只结束当前交互轮次，不停止整个询价功能；之后明确选择该列表机构且需求、平台未变、没有更新的功能或 requirement 时，恢复原询价分支并沿用原 requirement 与机构映射，不重新解析或落库。
- 原生补全前必须先调用对应平台登录准备工具（小红书 [pgy_auth_prepare](pgy_auth_prepare.md)、抖音 [douyin_auth_prepare](douyin_auth_prepare.md)，`{"action":"ensure"}`），登录窗口与验证码由宿主处理，不能重新启用已废弃的人工 Browser 流程；正常文件交付后不追加完成确认。
- 只有用户选择了对应动作，Agent 才继续该动作；关闭、取消、超时或无答案即结束当前轮次。结果不足时按 Skill 优先调整关键词和人设：已明确授权该范围则直接执行，未授权则先展示方案并等待确认。调整后仍不足，再展示实际数量、目标数量、缺口和其他可放宽的下一项；提出具体项后结束本轮，用户明确确认该项后才重新解析、落库和重跑。总体放宽授权不替代其他条件的逐项确认。
