# AskUserQuestion（宿主交互对话框）

需要用户选择、补充、确认或决策时，必须调用宿主 `AskUserQuestion`，不得用普通聊天文本提问。只要下一步依赖任何用户回复，就在同一轮调用本工具，绝不以问句、让用户打字或被动等待作为最终回复。问题只问用户可决定的、且缺失会实质改变结果的事项。

## 参数结构

```json
{
  "questions": [
    {
      "header": "标题（必填，如：悦普识星确认 / 悦普识星决策 / 下一步）",
      "question": "问题正文（必填，完整上下文）",
      "options": [{ "label": "选项短标签（必填）", "description": "选项说明（必填）" }],
      "multiSelect": false
    }
  ]
}
```

## 数量上限

- 一次调用最多 **4 个问题**；每个待澄清字段使用一个问题，并在同一次调用中成组提交。超过四项时，用户回答后重新解析，再提交下一组问题；不得把多个字段合并成警告。
- 每个问题 **2–4 个选项**，label 和 description 均非空。
- 选项必须是可执行的答案或动作：用户只点击 label 就能让流程继续，不能再要求用户另行输入该选项本该承载的值。
- 禁止使用“返回补充”“确认并补充”“自行填写”“请输入”等伪选项。对过期或缺失的时间，必须给出至少两个未来的绝对日期时间；对可编码的“不限”，直接规范化而不弹窗。
- `multiSelect` 必须显式声明：`true` 表示可多选（答案可共存），`false` 表示单选（答案互斥）。
- 宿主默认保留自定义输入框。不要添加虚假的 `其他` 选项、自定义字段参数或封闭式限制，也不要替用户选择默认答案。

## 展示规则

- `header`：简短分类标题；超过 20 个 Unicode 字符时同样换行。
- `question`：承载完整上下文（如缺失字段清单、风险提示；**MCN 机构名单表格除外**——它必须在调用 `AskUserQuestion` 前作为用户可见正文展示，`question` 只写决策问题）。内容太长必须**主动换行**：
  - `header`、`question`、`label` 和 `description` 的每一行都不得超过 20 个 Unicode 字符；
  - 优先在自然语义位置断行，连续长文本仍必须硬切分，多行用 `\n` 连接；
  - 机构名等选项标签允许插入展示换行，后续匹配前仅移除换行，还原原始完整名称。
- `label`：短动作词（如 `询价机构`、`结束本次`、`选择候选机构`），超长时按上述规则换行。
- `description`：一句话补充该选项后果，按上述规则换行。

## 展示模式与时机

`AskUserQuestion` 没有独立的 `type` 参数；警示、授权和普通决策都使用同一结构，通过标题、正文、选项和 `multiSelect` 表达。

| 类型      | multiSelect | 示例                          |
| --------- | ----------- | ----------------------------- |
| 决策/单选 | false       | `询价机构` / `手动拓展`       |
| 多选      | true        | 多平台、多字段同时确认        |

- **候选消歧**：当 Provider 返回机构名模糊或不唯一候选时，只展示真实候选并让用户选择；不得把已经成功发送的机构放入后续调用。
- **询价发送确认**：调用 `create_with_distributions` 前，必须完整展示最终机构名称列表和完整企微消息。用户选择 `确认发送`，或在该预览后明确回复“可以发”“发吧”“按这个发”“就这样发送”等无条件肯定表达时，可发送一次；否定、要求修改或带条件的表达不算确认。
- **不得预设答案**：选项顺序不表示推荐；用户拒绝/取消/关闭/超时/缺失答案是当轮终止，不得替用户推断或代选。

## Hook 生成的问题

- Hook 或保存结果给出 `ASK_USER_QUESTION_ARGS` / `delivery.next_args` 时，**逐字原样传递**，不得改写、删减或重排。
- 用户已明确说出 `询价机构` 或 `手动拓展` 时直接采用；`直接手扒`、`手扒`、`人工拓展`、`手捞筛选` 作为旧输入别名统一映射为 `手动拓展`。未明确、同时提到两种模式或语义冲突时，首次业务动作使用固定问题选择模式，回答前不解析、不落库。询价功能的 `rank_mcns` 排序成功后先输出完整 MCN 表格，再保存排名表并展示本地链接，最后调用保存结果给出的收件机构选择问题；不得再次询问业务模式。MCN 为空时先复核原需求、解析输出和实际落库参数，确认正确后才允许按 Skill 的顺序放宽。同一会话需求条件未变、前一功能完成或明确停止后改用另一功能时，复用现有 requirement，不再弹模式选择或重新落库。
- 登录、验证码、重试、暂停或结束人工 Browser 流程时必须弹窗；平台原生导出或对话名单成功交付后不追加完成确认。
- 只有用户选择了对应动作，Agent 才继续该动作；关闭、取消、超时或无答案即结束当前轮次。
