# 用户要求 Review Checklist

- [ ] 只有用户改变业务需求时才创建新版本；解析修正不算需求变更。只在必填信息缺失、冲突或确实含糊时询问，不默认、不从历史数据推断，也不要求确认整份 Brief。
- [ ] 金额、数量、比例、范围、平台、合作形式和指标档位按当前契约正确解析，未知或不支持的字段省略或保留在 Brief 中。
- [ ] Provider 检索单价只按原价向下 30%、向上 20% 扩展一次；Browser 手扒不得直接复用这个区间。
- [ ] 解析结果完整透传给校验工具；首次调用前按实时 schema 检查参数，只根据明确错误修正并最多重试一次。
- [ ] 主链路连续执行 `parse → validate → search_creators → ypscan_save_excel_artifact → rank_mcns`；搜索为 0 或用户直接要求人工拓展时也不跳步。
- [ ] 保留本轮 `search_creators` 返回的精确保存参数并立即调用保存工具；保存成功后再执行 `rank_mcns`，按“完整机构表格 → 真实本地 `file_path` → 后续分支弹窗”顺序输出。`creators_export_path` 只作为保存工具参数，不向用户输出下载链接，也不复用其他需求或平台的历史值；禁止用其他下载或写文件方式代替保存工具。
- [ ] 机构询价和人工拓展可并行、重复进入，互不阻塞；供给风险只提示，不默认放宽条件。
- [ ] `select_inquiry_form_fields` 必须用当前真实需求 ID 建立字段关联；用户提交后由 Provider 直接持久化。不得调用已弃用的 `get_selected_inquiry_form_fields`，不得轮询 callback，也不得在 Agent 上下文读取、重建或缓存 `columns`。
- [ ] `create_submission_batch`、`create_with_distributions`、`get_creator_detail_export`、`get_creator_detail` 不传 `columns`，只传当前 schema 要求的业务标识并由后端关联字段；已弃用的 `manual_source_creators` 不得调用。收到 Excel URL 后立即保存并展示真实本地路径。
- [ ] 需要用户决策或补充信息时必须调用 `AskUserQuestion` 弹窗，提供简短、可执行的选项；不得用普通聊天问句停住流程。
- [ ] Agent 必须自主完成所有可执行步骤并持续推进；不得随意要求用户代为操作、整理信息、输入“完成”或帮助排错。仅在缺少必要授权、必要输入、登录或真实 CAPTCHA 等无法自主完成的情况下暂停。
- [ ] 企微正式发送是唯一业务审批；确认绑定完整参数且仅消费一次，参数不变只发送一次，参数变化必须重新确认，其他操作不得新增审批。
- [ ] 不绕过正式发送工具和宿主确认，不记录或固化密钥、Token、Cookie、密码或验证码。
- [ ] 机构表格展示机构名、返点、综合分和本机构覆盖数；缺失写“未知”，覆盖和供需指标只按当前响应的真实数据计算。
- [ ] `rank_mcns` 每行覆盖人数只取当前机构自己的 `candidate_count` 原值；`mcn_covered_creator_count` 是累计字段，不得用作本机构人数，不得与前序机构累加，也不得用其他累计/聚合覆盖字段或相邻行差值替代。
- [ ] `supplier_id` 与机构名来自同一轮结果并逐一匹配；映射失败时停止发送准备，不靠重复排序猜测修复。
- [ ] 所有结果、链接、文件和状态来自真实返回值，并归属于当前需求和平台；同一需求多批结果按平台稳定 ID 去重，不混入其他数据。粗召回、复核候选和最终名单须明确区分，自有 Excel 遵循客户模板。
- [ ] Browser 人工拓展只在固定 Provider 链路和用户选择后进入；Agent 打开正确达人页并调用 `ypscan_manual_research`，不猜控件、不跨行拼接数据。
- [ ] 页面普通提示、资质提醒、新手引导、遮罩或遗留浮层由 Agent/工具直接关闭或复位，不要求用户代操作；登录失效、真实 CAPTCHA，或详情请求出现 401、403、429 时暂停整个详情批次，风控信号不自动重试。
- [ ] 手扒调用参数保持精简：只传 `requirement_id`、`platform`、页面可表达的最小 facts，必要时传 1–4 个关键词；省略 `page_url`、`original_brief` 和默认/审计字段。
- [ ] 手扒达人单价以客户原始值为锚点向下拓展 50%、向上拓展 20%，即筛选客户值的 50%–120%；例如“10 万以内”必须筛 5 万–12 万，不纳入低于 5 万或高于 12 万的达人。显式区间 `[A,B]` 使用 `[0.5A,1.2B]`。
- [ ] 手扒价格扩展只作用于达人单价，不扩展 CPM、CPE、粉丝数或总预算；蒲公英严格区分图文/视频价，星图严格区分 1–20 秒、21–60 秒、60 秒以上报价，禁止跨形式、跨时长替代。
- [ ] 手扒先使用真实 UI 产生的列表响应并以 DOM 补全，可执行多关键词硬筛与分页；平台原生导出仅在候选不足、关键字段完全缺失或列表读取异常时触发一次，不作为起始步骤，不按关键词重复消耗额度。
- [ ] 区分硬条件、软条件和待核实项；硬条件不放宽，软条件降级要标注风险，不同内容形式和时长的报价不得互相替代。
- [ ] 人工拓展支持分批交付；供给充足时达到目标数量，不足时明确说明缺口。目标超过 20 人时对话只给摘要、待确认项和最多 10 条预览，不粘贴完整名单。
- [ ] 每读完一页候选就增量追加到当前项目 `checkpoint.jsonl` 并强制落盘；同一需求、平台和筛选计划在上下文压缩、Gateway 重启或输出截断后能自动恢复最新 run。显式“重新实时手扒”创建隔离的新 run 并更新本地 latest 指针，随后普通续跑省略 `fresh_run` 仍能恢复该 run。
- [ ] 手扒完成、部分完成或登录/CAPTCHA/详情风控中断时都生成并持续刷新同一个本地 Excel，固定含“最终名单”“详情补录”“完整候选池”“条件判断”“运行信息”；最终回复必须展示真实 `artifact.excel_path`，本地 Excel 不消耗平台导出额度。
- [ ] 平台专属功能不得跨平台调用；人工拓展只使用宿主 Browser 和 `ypscan_manual_research`，不恢复旧 Runner、Cookie/Token 导出、签名逆向或脱离浏览器的私有 API。
- [ ] 工具卡、Skill、Hook、MCP schema、数据库字段和实际流程保持一致；错误需分类并用用户能理解的话说明影响与下一步。
- [ ] 修改前定位真实原因，只做最小改动；不新增无必要的状态、缓存、账本、校验实体或权限门禁，共同逻辑保持共享。
- [ ] 测试覆盖核心流程、Browser 分支、去重、导出、发送确认和失败路径；mock 不替代真实样本与平台验收。
- [ ] 修改后执行 lint、typecheck、test 和 smoke；不跳过失败、不降低断言、不修改测试制造成功。
- [ ] 发布前验证真实安装流程和包内容；Review 结论必须基于当前代码、真实响应或可复现测试，并区分已验证、推断、未知和外部依赖。
