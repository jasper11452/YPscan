范围：本地 ypscan 1.0.25 开发目录，未发版、安装或部署。起始工作区干净。

## 证据与修复

`src/tools/read-creator-preview.js` 原先收集非法行后，只要 `problems.length > 0` 就返回 ROWS，导致其他机构的正确行无法继续补全与评分。新增隔离样本：机构甲主页与 ID 不匹配、机构乙正确、机构丙缺 ID/主页。修复前测试退出 1；修复后仅机构乙进入 CSV，错误明细保留原表行号、所属机构和原因，原始 Excel 字节不变。全部无效仍报 ROWS，不生成空评分表。

Hook 在 links 成功后输出错误行提示并继续有效行；机构采集 `partially_succeeded` 原本已保存 Excel，本次补充失败消息及“不等待失败机构修正”的指引。表内没有“所属机构”时只报行号，不推断机构；采集错误只在真实错误支持时归因为填写不正确。

测试环境 Provider metadata 审计退出 0，输出保存在 `/tmp/ypscan-ingest-schema-audit-20260914.json`。它只核对工具元数据，不证明远端能从混合失败机构生成预览。仓库没有 Provider 采集实现；没有本次真实失败任务响应，无法确认用户遇到的阻断是否还发生在远端。

## 类似阻断风险

等级表示对交付的影响与处理优先级，不表示应当无条件取消校验。

| 等级 | 位置与行为 | 评估与处理 |
| --- | --- | --- |
| 高，已修 | `read-creator-preview.js` 任意非法行拒绝整表 | 可独立识别行级错误，现排除错误行并报告，正确行继续。 |
| 高，待真实证据 | `register-flow-directives.js:getIngestJobDirective` 失败 envelope/任务失败暂停；远端可能未返回 Excel | 如 Provider 本身整体失败且未产出文件，客户端无法生成成功机构的预览。需真实 job 响应及服务端实现定位，不能把整体失败伪装为成功。 |
| 高，未改 | `manualSourceCompletionDirective` 显式 success=false 或某批无 csv_file 停止后续；机构可能已有其他成功批次 | 有扩大局部失败影响的风险。需要核对宿主实际成功/失败名单、可用 CSV 及来源登记，再设计只合并成功批次；本次不猜测原生返回契约。 |
| 中，未改 | `save-creator-links.js:readLinksCsv` 手动拓展 CSV 单行非法拒绝整份 | 同类可用性风险，但属于另一输入链路；其人数与候选统计契约需同步设计。当前机构预览路径已修，不顺带修改手动拓展。 |
| 中，未改 | `merge-creator-csv.js` 任一补全 CSV 缺 ID 表头或解析失败拒绝合并 | 会影响其他文件，但不能猜测坏文件身份列。后续可评估以已登记成功批次为单位隔离并明确缺口。 |
| 中，保留 | `manual-score-summary.js` 未知结论、无效分数、结论冲突或评分缺行停止最终汇总 | 保护推荐计数与结果真实性；已有可信单批表降级交付规则。需独立规则才能排除异常行，不能默默丢弃。 |
| 必要阻断，保留 | 来源/需求/平台不匹配、哈希变化、表头歧义、无法安全合并模板、上传不可读、全部行无效 | 防止混用结果、损坏文件或假交付。失败时保留已有可信文件，不以跳过校验解决。 |
