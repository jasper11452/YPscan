### 资格待核实、排序与空白列的原因

对最终表三个现象的代码级复核；原始逐人模型 JSON 本轮无法重读（Dify 控制台会话已失效），结论来自已发布工作流代码与提示词、最终表文案和需求原文，不冒充节点回读。

- **资格待核实**：`final` 节点是状态机：任一 `must_have`/`must_not` 条件既非 PASS 也非 FAIL（UNKNOWN）就进入 `qualification_pending`，档位写“资格待核实”、结论“不推荐”。本轮触发项：①“合作形式为报备视频/植入视频”——原生补全数据没有这个可核验字段，模型只能给 UNKNOWN；②“综合分不为 0”——这是交付规则，被解析成达人硬条件（宋宋的劣势直接写“无法确认是否满足 H4”），程序在打分前无法自证自己即将算出的分数，永远 UNKNOWN；③报价缺失（咸淡超人、谈家二姑娘）——价格核验返回 UNKNOWN 而不是 FAIL。解析节点每个达人各跑一次，同一句需求有时进 `must_have`、有时不进，所以“琴儿家”理由说“无法满足报备视频”却仍是推荐。文案看起来含糊是因为 `final` 把每个条件名截到 18 字、最多列 2 条，整句再截到 90 字。
- **上述门禁已按用户决定修改并发布**（`912d3cdb-aaed-42f8-969e-faf526e0cf3f`，hash `fe9a36d0…11ab`）：`final` 不再把 `pending` 升级为 `qualification_pending`，UNKNOWN 只在推荐理由末尾标注“待确认：…”，只有已确认 FAIL 仍判硬约束失败；“综合分”加入非达人侧条件过滤，解析提示词也明确交付/质量门槛不写入任何达人条件字段；复核提示词同步为“UNKNOWN 只标注待核实、不因此判不推荐”。回放 `scripts/replay-dify-status-gates.py` 7/7。现有最终 Excel 生成于该发布之前，仍显示旧的资格待核实/不推荐；新行为需重跑评分后用真实结果验收。
- **不推荐排在推荐前面**：原实现由 `src/tools/manual-score-summary.js` 的 `rows.sort((a, b) => b.score - a.score)` 排序，只按综合分降序，`推荐结论` 不参与排序键；同分按候选顺序，因此 88.4 分的“咸淡超人（不推荐）”排在 77 分的“悦己（推荐）”之前。现已按用户 2026-09-10 决定改为综合分（0.7×相关度＋0.3×同批性价比）降序、同分按性价比降序；`推荐结论` 仍不是排序键，综合分更高的“不推荐”行仍可能排在“推荐”行之前，若要“推荐优先”需另行确认。
- **达人优势/劣势空白**：`final` 在复核有效时用复核节点的 strengths/weaknesses（`copy_source = reviewed if review_status == 'ok' else scored`）。复核提示词明确允许留空（“没有足够依据时少写或留空”“无已确认短板时允许空数组”）；`_strip` 还会删掉没有评论/正文证据支撑的表述（如无正文时不能写“口播、讲解清晰”），`_copy_items` 把“证据上限修正：”等诊断移出交付列。空白表示过滤后没有可交付依据，不是数据丢失：金金猛火厨房无已确认劣势，大头大头无足够依据写优势。

### 已实施：综合分纳入性价比（2026-09-10）

用户确认权重 0.7/0.3、同意 XHS 代理口径、要求不改 Provider 模板、只改写最终表“综合得分”列。实现落在 `src/tools/manual-score-summary.js`：综合分 = 0.7×Provider 相关度分 + 0.3×性价比分；性价比在同批同平台内按商业成本做百分位归一化（成本越低分越高），抖音用 `植入视频-预期CPM`（60%）与 `植入视频-预期CPE`（40%），小红书用代理口径 `视频笔记一口价 ÷ 合作_视频&图文_阅读中位数 × 1000`（缺失回落日常阅读中位数）与 `视频笔记一口价 ÷ 合作_视频&图文_互动中位数`（同样回落日常）；缺失按同批中位数代入并返回 `cost_effectiveness_pending_count`，整批无商业数据时保留原相关度分。最终表按综合分降序、同分按性价比降序；“匹配等级”仍是 Provider 相关度档位；0 分排除仍以 Provider 原始相关度为准。

### 剩余准确性边界

本轮没有放宽类型标准、改变评分权重或降低预算/粉丝验收门槛，也没有把 12/11 个程序“推荐”全记作通过。除前述小红书矛盾，抖音“悦己（湖南特产）”在两个需求基本一致的独立批次中由 52 分不推荐变为 77 分推荐，R2 仍写“无法确认是否展示食材和做法步骤”；该样本不列入人工核验的 5 人。两次不是完全相同的序列化输入，不能据此单独归因于模型随机性，但足以说明边界类型仍需稳定性回归。

R2 共 30 行均为非 0 分，未在真实运行中命中综合分 0 的分支；该分支仅有现有自动化测试，不冒充真实零分样本通过。旧表里报价缺失的“咸淡超人”“谈家二姑娘”因资格待核实未推荐；按新发布规则，缺失或无法核验只标注“待确认”，是否进入推荐必须重跑评分后用真实结果核对，不能把旧表结论当新行为。错类型的“骏弟鉴好物”“大头大头”均未推荐。完整无人干预验收仍被评分文案矛盾与解析条件漂移阻断；字段继承按用户指示本轮不测。
