## 推荐质量证据与责任边界

N=20 的 batch626/627 确认存在推荐集合翻转：4人对3人，集合 Jaccard 0.75，同候选结论一致率80%。此前建议的0.8/85%尚未成为已确认的业务验收标准，不能仅据此宣布违反正式指标。

争议行从62.6分/推荐变为50.1分/不推荐，类型匹配分22.5变为15。原始需求要求真实教师身份，而该行自我介绍缺失；第一轮理由表示无法确认身份，劣势却写成“不满足硬性要求”，同时给出推荐。因此已证实的是 UNKNOWN 与 FAIL 的文案矛盾、资格待核实时两轮判定不同，不是已经证明此达人实际身份不符。真正明确硬失败的另一行第一轮已是不推荐。

两份补全 CSV 的该达人89列中只有粉丝画像变化，但两轮 validate 的项目名和部分解析标签也不同；还缺 Provider 组装给 Dify 的实际需求、线上工作流版本、模型采样参数与原始结构化结果，不能把翻转归因于纯模型随机。

N=20 四份单批/汇总表没有上一轮所称的“返点缺失”理由文字；N=2 表中确实有此类文字，不能混用样本。返点未知本身不构成当前候选推荐语义的缺陷，见[既有方案的语义边界](../plans/creator-search-and-scoring-remediation.md) §2.3、§6。插件按现行契约读取 Excel“推荐结论”计数，不解析理由或自行改分。资格状态导出、资格未知不计数的新口径是 P1b 跨系统待实施契约，本轮没有提前启用。
